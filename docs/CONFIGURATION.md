# 配置与通用模板

## 筛选条件

所有列表字段都建议用**英文逗号 `,`**分隔，例如 `广州,深圳`。岗位、城市各自“任一词匹配”；这两组和其他已启用条件同时生效。

| 字段 | 示例 | 规则 |
| --- | --- | --- |
| 岗位关键词 | `前端开发,Web,AI,Agent` | 标题包含任一词；留空不限 |
| 城市关键词 | `广州,深圳` | 城市包含任一词；留空不限 |
| 排除词 | `销售,培训` | 卡片文本命中任一词就跳过 |
| 经验 / 求职类型 | 不限、实习/在校、应届/经验不限 | 只根据卡片文字判断，未出现相关标签可能被排除 |
| 学历标签 | 不限、包含“大专”等 | 按卡片包含相应文字判断，不进行学历等级推断 |

筛选不会阅读岗位详情全文。预览只展示当前已加载的卡片，不会发起沟通。像 `AI` 这样较短的词可能匹配较宽，建议先预览。

## 手机默认招呼语

岗位列表的“立即沟通”由网站自身触发招呼机制，先在自己的 BOSS 账户中确认招呼语；可以通过手机 App 中提供的入口设置。电脑与手机需使用同一账户。具体功能是否可用以 App 当前页面为准。

不包含个人经历的通用示例：

```text
您好，我对贵公司的岗位很感兴趣，想进一步了解岗位要求和工作内容，方便沟通吗？
```

## 聊天页默认话术

位置：齿轮 → 沟通话术。公开版默认提供以下模板：

```text
您好，我想应聘贵公司的[目标岗位]。我具备[相关技能/经验]，预计[到岗时间]可以到岗。方便进一步了解岗位要求吗？
```

只填写自己的真实资料；所有方括号应替换或删去。作者署名不会自动进入话术。脚本会阻止直接启动仍含默认占位符的聊天发送。

这段话术不替代列表中的 BOSS 默认招呼语。聊天流程由用户在聊天页单独启动，先处理话术，再检查简历入口；已有手动草稿不会覆盖。话术没有确认回显时会保留待核对状态，避免反复重发。请先核对真实会话；停止后“清记录”会清除全部 HR 处理及话术/简历进度。

## 投递参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 每轮最多投递 | 30 | 按沟通按钮点击计数，包含已有会话 |
| 每批投递数 | 8 | 到达批次后休息 |
| 沟通后等待 | 5–9 秒 | 每次随机取值 |
| 批次休息 | 45–90 秒 | 每次随机取值 |

设置用秒显示，内部保存为毫秒；最少时间不能大于最多时间。运行时条件锁定，先停止再修改。紧凑模式和已有设置会保留在当前网站域名的浏览器存储里。

## 可选 AI

位置：齿轮 → AI 自动回复。**默认关闭**，不配置也能使用列表沟通。

开启时填写自己选择的兼容接口地址、模型和 Key，再将人设补充为真实求职资料。默认人设只规定礼貌沟通、不编造经历，不包含作者的简历。AI 只在聊天流程对应的分支中使用，不会对每个列表岗位生成个性化招呼语。

API Key 保存在当前站点的浏览器 localStorage 中，不写入发布脚本；启用 AI 后，最近 HR 消息和人设会发送至用户配置的接口。不要把真实 Key、求职记录或聊天截图提交到 GitHub。`@connect *` 用于允许配置不同 AI 域名，不代表脚本会主动向所有域名发请求。

## 数据与运行边界

- 存储前缀沿用 `hz_boss_helper_v2_`；同域名、同浏览器下保留旧设置和 HR 记录，公开模板不自动覆盖旧话术。
- 刷新后不自动运行；跨页面路径切换会停止并提示在新页面手动启动。
- 本轮按岗位标识去重；没有 ID 时用标题、公司、城市、薪资和标签组合，不能完全区分这些信息相同的岗位。
- AI 的最近消息文本去重只在当前标签页内保留，不跨刷新持久化。
- 日志保留最近 120 条，可复制或导出 TXT；计数表示操作和回显检查，不保证网站最终送达。
